Abstract

This report presents the design, development, and deployment of a Library Management System (LMS) built as a full-stack web application using the ASP.NET Core 8 MVC framework and Microsoft SQL Server Express. The system provides an integrated digital platform for managing library resources including books, students, librarians, borrowing records, and publications such as newspapers and magazines.

The application follows the Model-View-Controller (MVC) architectural pattern, leveraging Entity Framework Core 8 as the Object-Relational Mapper for structured data access, supplemented by parameterised raw SQL queries for performance-critical operations. ASP.NET Core Identity is integrated for authentication infrastructure. The user interface is built with Bootstrap 5.3 and Razor view templates, delivering a responsive and browser-agnostic experience.

The project was developed, tested, and version-controlled using Git with the complete source code hosted on GitHub. All major modules — book cataloguing, borrowing and return workflow, student and librarian management, publications tracking, and a real-time statistical dashboard — were implemented and verified against a live SQL Server Express instance.

Keywords: ASP.NET Core 8, MVC, Entity Framework Core, SQL Server, Library Management, C#, Razor Views, Bootstrap 5

Section 1

Introduction and Objectives

Traditional library management relies heavily on manual record-keeping processes that are error-prone, time-consuming, and difficult to scale. This project addresses those challenges by delivering a fully digital, web-based Library Management System that automates the core administrative functions of a library.

The system is accessible through any standard web browser, requires no client-side installation, and is backed by a robust relational database. It centralises the management of books, student and librarian records, borrowing and return workflows, and publication archives within a single, cohesive platform.

1.1 Objectives

  • Design and implement a multi-module web application using the ASP.NET Core 8 MVC pattern.
  • Provide complete CRUD (Create, Read, Update, Delete) functionality for books, students, librarians, and publications.
  • Implement a borrowing and return workflow with real-time availability tracking.
  • Deliver a real-time administrative dashboard aggregating statistics from all modules.
  • Integrate ASP.NET Core Identity for secure authentication infrastructure.
  • Manage source code with Git and publish to a public GitHub repository.
  • Ensure the system is maintainable, extensible, and follows software engineering best practices.

1.2 Scope

The scope of this capstone project encompasses the full software development lifecycle including requirements analysis, system design, implementation, database migration, testing, and version control. The system was developed and tested on a Windows environment with .NET 8.0 SDK and SQL Server Express 2017.

System Architecture

The application adheres strictly to the Model-View-Controller (MVC) architectural pattern enforced by the ASP.NET Core framework. This pattern enforces a clean separation of concerns: the Model layer encapsulates domain entities and data access logic; the View layer contains Razor templates responsible solely for HTML rendering; and the Controller layer handles HTTP request routing, orchestrates data retrieval, and selects the appropriate view response.

3.2 Data Access Strategy

The project employs a dual data access strategy. Entity Framework Core is used for the Books13, BorrowRecords13, and Publications tables, where the ORM's change tracking and relationship navigation provide productivity benefits. For the Students and Librarians tables, parameterised raw SQL via Microsoft.Data.SqlClient is used directly, demonstrating proficiency with both abstracted and explicit database interaction patterns.

3.3 Dependency Injection

ASP.NET Core's built-in Dependency Injection container is used to register and resolve services. Both LibraryContext and ApplicationDbContext are registered as scoped services in Program.cs, along with the Identity services. Configuration values (connection strings) are injected into controllers via IConfiguration.

Section 6

Modules and Feature Description

6.1 Book Management Module

Managed by BooksController using Entity Framework Core and the LibraryContext. Provides full CRUD operations: listing all books with paginated output, searching by title or author, adding new book entries, editing existing records, and deletion with cascade effect on associated borrow records. Each book's IsAvailable flag is toggled automatically during borrow and return transactions.

6.2 Borrow and Return Workflow

Managed by BorrowController using async EF Core operations. When a student borrows a book, the system verifies the book exists and its IsAvailable flag is true. A BorrowRecord is created, and the book is marked unavailable. On return, ReturnDate is set to the current UTC timestamp and the book is re-marked as available. All operations are protected by AntiForgery tokens.

6.3 Student Management Module

Managed by StudentController using raw parameterised SQL via SqlConnection. Supports server-side search filtering by name and paginated listing (5 records per page) using SQL OFFSET / FETCH NEXT syntax to prevent SQL injection.

6.4 Librarian Management Module

Managed by LibrarianController with raw SQL and IConfiguration-injected connection strings. Full CRUD is supported: listing with pagination, name-based search, create, edit, and delete via direct SQL statements with parameterised values.

6.5 Publications Module

Managed by PublicationsController using EF Core with the Publication entity. Publications are categorised by a PublicationType enum (0 = Newspaper, 1 = Magazine). The index view accepts a type query parameter and filters accordingly. Pagination is implemented server-side.

6.6 Dashboard Module

Managed by DashboardController using raw SQL scalar queries across all five data tables. Each count query is enclosed in an individual try-catch block to ensure partial data still renders if a single table query fails. Connection strings are injected via IConfiguration.

6.7 Authentication Module

Managed by LoginController. Provides a login form and verifies credentials against an in-memory list (suitable for demonstration purposes). On successful authentication, the user is redirected to the dashboard. The ASP.NET Core Identity middleware pipeline (UseAuthentication, UseAuthorization) is fully configured in Program.cs for future extension.

public async Task<IActionResult> Create(BorrowViewModel model) { var book = await _context.Books13.FindAsync(model.BookId); if (book == null) return View("NotFound"); if (!book.IsAvailable) return View("NotAvailable"); var record = new BorrowRecord { BookId = book.BookId, BorrowerName = model.BorrowerName, BorrowerEmail = model.BorrowerEmail, Phone = model.Phone, BorrowDate = DateTime.UtcNow }; book.IsAvailable = false; _context.BorrowRecords13.Add(record); await _context.SaveChangesAsync(); return RedirectToAction("Index", "Books"); }

8.2 Razor Tag Helpers and Validation

All form views use ASP.NET Core Razor tag helpers for clean, maintainable markup: asp-controller, asp-action, asp-for, and asp-validation-for. The @Html.AntiForgeryToken() helper is included on every POST form to prevent Cross-Site Request Forgery (CSRF) attacks. The [ValidateAntiForgeryToken] attribute is applied to all corresponding POST action methods.

8.3 ViewModel Pattern

View-specific data requirements are addressed through dedicated ViewModel classes rather than passing domain models directly to views. For example, LibrarianIndexViewModel encapsulates the list of librarians alongside pagination metadata (current page, total pages, page size, search term), keeping the view layer decoupled from data access concerns.

Setup and Installation Guide

9.1 Prerequisites

.NET 8.0 SDK

Download from dotnet.microsoft.com. Verify installation with dotnet --version.

SQL Server Express (any edition)

SQL Server Express 2017 or later. Ensure the MSSQL$SQLEXPRESS service is running.

Git

Required to clone the repository. Verify with git --version.

EF Core CLI Tool

Install globally: dotnet tool install --global dotnet-ef

9.2 Step-by-Step Installation

# Step 1 — Clone the repository git clone https://github.com/Kavyansh180/Library-Management-System.git cd Library-Management-System/LMSystem # Step 2 — Install EF Core CLI tool (if not already installed) dotnet tool install --global dotnet-ef # Step 3 — Apply EF Core migrations (creates LMS and IdentityCoreDB) dotnet ef database update --context LibraryContext dotnet ef database update --context ApplicationDbContext # Step 4 — Create raw SQL tables (Students and Librarians) sqlcmd -S .\SQLEXPRESS -d LMS -Q " IF NOT EXISTS (SELECT * FROM sysobjects WHERE name='Students') CREATE TABLE Students (StudentId INT IDENTITY(1,1) PRIMARY KEY, Name NVARCHAR(100) NOT NULL, Age INT NOT NULL, Phone NVARCHAR(20) NOT NULL); IF NOT EXISTS (SELECT * FROM sysobjects WHERE name='Librarians') CREATE TABLE Librarians (LibrarianId INT IDENTITY(1,1) PRIMARY KEY, Name NVARCHAR(100) NOT NULL, Age INT NOT NULL, Phone NVARCHAR(20) NOT NULL);" # Step 5 — Run the application dotnet run # Application is now accessible at: http://localhost:5000
Note: The connection strings in appsettings.json target .\SQLEXPRESS with Windows Integrated Security. If your SQL Server instance name differs, update the Data Source value accordingly before running migrations.

Conclusion and Future Scope

11.1 Conclusion

The Library Management System capstone project demonstrates the successful application of full-stack web development concepts using the Microsoft .NET ecosystem. The project covers all core aspects of modern enterprise web application development:

  • Architectural discipline: Strict adherence to the MVC pattern with clear layer separation through Controllers, Models, ViewModels, and Views.
  • Dual data access: Effective use of both Entity Framework Core (ORM-based) and raw parameterised SQL, demonstrating proficiency with both abstracted and explicit data access approaches.
  • Security foundations: AntiForgery token protection on all POST forms, parameterised queries preventing SQL injection, and ASP.NET Core Identity middleware integration.
  • Responsive design: Bootstrap 5.3 integration ensuring a consistent, mobile-compatible user experience across all pages.
  • Database management: Demonstrated competency with EF Core migrations for schema management across two separate SQL Server databases.
  • Software engineering practices: Version control with Git, structured project layout, clean commit history, and published source code on GitHub.

All twelve modules have been implemented, tested, and verified against a live SQL Server Express instance. The project was completed without errors and the full source code is available at the repository listed on the cover page.
